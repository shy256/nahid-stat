# 项目完整规范与文档地图

本文件由根目录 `AGENTS.md` 引用，作为整个仓库的项目规范。局部目录规范可以补充模块细节，但不能静默放宽仓库级红线；出现冲突时遵循上级系统、开发者和用户指令，再结合适用范围处理。

## 当前项目边界

- 仓库根目录为 `J:\mazda`；文档和命令中的相对路径均以仓库根目录为基准，Markdown 链接则以所在文件为基准。
- 当前为基于 Bun、TypeScript、SQLite 的轻量个人网站统计服务，运行时无第三方依赖；开发类型依赖见 `package.json`。
- 服务入口 `src/index.ts`，浏览器脚本与管理看板位于 `public/`，配置、接口、数据口径和已知限制见 [统计模块](./modules/analytics.md)。
- 默认不持久识别访客，初版统计 PV 和事件次数，不计算 UV、会话或跳出率；部署状态与操作记录见本地 `_internal/`。

后续按实际需要新增专题文档，例如 `.agents/modules/<module>.md`。创建专题文档时，必须补充本表或项目地图中的入口，避免形成无人知晓的文档。

`_internal/` 不随克隆分发，首次使用时在仓库根目录自行创建；入口为 `_internal/README.md`，部署记录写入 `_internal/deployments.md`。公共文档仅登记目录用途，不复制内部部署内容。该目录仍遵守敏感信息红线，凭据仅记录配置项名称或安全存储位置。

## 工作流程

1. 明确用户目标与影响范围，读取热索引命中项、相关专题文档及适用的局部 `AGENTS.md`。
2. 优先使用 `rg --files` 和 `rg -n` 定位文件与代码，避免默认扫描生成物、依赖目录或历史归档。
3. 用当前代码和命令验证已有记录；先建立能解释问题的最小复现，再实施范围明确的修改。
4. 运行与变更相关的验证。没有验证条件时，如实记录未验证项，不把缺少测试套件描述为测试通过。
5. 检查差异和敏感信息，必要时更新专题文档及热索引，用中文说明修改结果、验证证据和剩余限制。

## 关键红线

- 不将密钥、令牌、Cookie、个人信息、生产敏感数据写入代码、文档、记忆或 Git；示例配置使用占位值。
- 不覆盖用户已有改动；执行破坏性 Git 操作或删除文件前明确目标和影响，不能把清理环境作为默认步骤。
- 不自行发布、部署、推送或修改生产状态；这些操作必须在用户授权范围内执行。初始化本地 Git 不代表已获授权创建远程仓库。
- 不编造运行命令、测试结果、模块结构或服务状态，不把计划写成已完成事实。
- 冻结协议必须有明确的协议文件或用户确认依据；若后续引入，在本文件登记入口、范围和变更要求。
- 记忆的格式、压缩阈值、遗忘处理和敏感信息限制遵循根目录 `AGENTS.md`，不在归档中保留已失效的冲突结论。

## 专题文档维护

- 文档描述当前可复核的事实，历史原因只保留仍能解释设计决策的部分。
- 模块专题建议包含：职责、入口文件、依赖、接口或数据约束、验证命令、已知限制。
- 实际命令应标明运行目录、前置条件和预期结果；配置与运行状态变化后同步修正文档。
- 已稳定的长篇模块知识存入专题文档，热索引只保留简短结论及指向证据的链接。
